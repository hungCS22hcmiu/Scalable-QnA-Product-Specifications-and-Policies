### 2026-09-05  ·  ~1 hour  ·  Day 0 of the MVP push — de-risk the demo before building

**Did:** Measured whether the lookalike trap the whole research demo rests on actually works on
`dev-v0`, before spending three days building Tier 2 around it. Ran `rag.retrieve` and
`rag.embedding` directly — no gateway, no gRPC — on candidate query pairs.

| Pair | sim | overlap | τ-only (0.85) | Rule (0.85, 0.6) |
| :--- | ---: | ---: | :--- | :--- |
| Paraphrase — "Is a 20-day return possible for this laptop?" | 0.965 | 1.00 | REUSE ✓ | REUSE ✓ |
| Unrelated — "How long does shipping take?" | 0.532 | 0.40 | refuse ✓ | refuse ✓ |
| laptop vs sofa | 0.848 | 0.40 | refuse | refuse |
| **headphones vs desk** | **0.851** | **0.40** | **REUSE — wrong** | **refuse — correct** |
| policy-heavy phrasing, headphones vs desk | 0.865 | 0.60 | REUSE — wrong | **REUSE — also wrong** |

Non-citable throughout: `dev-v0` (ADR-020), demo θ/τ, functional run.

**The trap works — use headphones-vs-desk for demo step 4.** It is the pair where a fixed
threshold reuses and returns the wrong answer while containment refuses, which is exactly what
`defense_demo.md` §4 requires of that step.

**The Day-0 worry did not materialise, and the real problem is a different one.** The concern was
that 44 chunks at `top_k=5` retrieves 11 % of the corpus per query, so overlap would be high
everywhere and the signal flat. **Overlap separates cleanly** — 1.00 for a true paraphrase, 0.40
for a cross-category lookalike — and retrieval ranks the correct policy first in both directions
(electronics 0.776 for the laptop query, furniture 0.778 for the sofa query).

**Similarity is what lacks range.** Every query of the form *"can I return X after N days"* lands
in **0.848–0.865 regardless of X** — laptop, sofa, headphones, desk. The embedding barely
separates product category inside a shared template. Two readings, both worth carrying:

1. **It supports the premise of C1.** Similarity is a weak discriminator in exactly the band where
   the reuse decision is hard. A τ sweep has almost nothing to sweep here.
2. **It makes the demo margin fragile.** 0.851 against τ=0.85 is a **0.001** margin. Rehearsed
   answer recorded in `slides.md`: that fragility *is* the argument for a second orthogonal
   signal, not a weakness to hide.

**A false hit the rule does not catch, recorded deliberately.** The policy-heavy phrasing of the
same pair yields overlap **0.60 = θ exactly**, so the rule reuses and is also wrong. A real
limitation inside the δ ≤ 5 % budget. Stated up front rather than left for a committee to find.

**Carried into W8's actual scope as a requirement, not a nice-to-have.** `v1` must be built for
**frontier dynamic range**, not only to pass the G1/G2/G3 gate. If every query family sits inside a
0.02-wide similarity band, config 3's τ sweep degenerates and Headline B loses resolution. This is
a new constraint on `v1` that ADR-024/ADR-028 do not currently state — raise it when scoping the
corpus.

**Decisions:** two, neither needing an ADR.

1. **Do not extend `dev-v0` before the pitch.** Four days cannot absorb both a corpus rebuild and
   Tier 2, and the trap already works. Corpus diversity is a W8 concern.
2. **Split `make dev` from `make measure`.** `dev` was gating on
   `kern.memorystatus_vm_pressure_level == 0`, which is stuck at `1` here, so it blocked all MVP
   work — the standing pressure that makes a strict guard get quietly weakened (rule #10). Now
   `dev` is functional-only (`memorystatus_level ≥ 25 %`, no `env-check`, no zone gate) and prints
   a **"numbers are NOT citable"** banner every run; `measure` keeps the full proposal §7 rule.
   The hazard was never the relaxed run — demo runs produce no citable number, since every
   headline figure is pre-computed and the load clip pre-recorded (`defense_demo.md` §4). The
   hazard is a demo latency drifting onto a slide, which is what the banner exists to stop.
   *Implementation note:* the memory check first used `free+purgeable`, which read **0.4 GB** on a
   machine with **60 % available** — macOS reclaims inactive pages, so free pages badly understate
   what can be allocated, and the check would have failed constantly. `kern.memorystatus_level` is
   the signal that tracked correctly all through 2026-09-04.

**Blockers:** none. F1 (`OLLAMA_NUM_PARALLEL`) and the pressure-sensor reboot test both remain
open and both block W8's μ_hit probe, **not** the pitch.

**Next:** Days 1–2 build Tier 2 (`embed/`, `idx:cache` FLAT 768-dim, `t2:` records **with
`t1_key`**, write-back to both tiers). Day 3 the containment rule. Day 4 slides, then UI if time.

### 2026-09-05 (later)  ·  ~3 hours  ·  Tier 2 + the containment rule — days 1-3 of the MVP push

**Did:** Built the entire missing half of the demo in one session. All four demo steps now run,
twice in a row without touching code (`defense_demo.md` §4's rehearsal gate).

| Step | Result | sim | overlap | latency |
| :--- | :--- | ---: | ---: | ---: |
| 1. Fresh question (headphones → electronics, 30-day window) | `MISS` | — | — | 3.8 s |
| 2. Exact repeat | `TIER1_HIT` | — | — | **0 ms** |
| 3. Paraphrase | `TIER2_HIT` | 0.935 | 0.800 | 40 ms |
| 4. **The trap** (desk → furniture, 14 days + 15 % fee) | **`MISS`** | **0.851** | **0.400** | 3.6 s |

Step 4 is the research claim, executing: similarity **clears** τ=0.85, containment **fails**
θ=0.6, the rule refuses, and the correct furniture answer is generated instead. The gateway log
carries the counterfactual explicitly —

```
cascade similarity=0.8506 overlap=0.40 reuse=false similarity_only=true entered_band=true
  retrieved=[policy-returns-electronics#0 policy-returns-furniture#0 product-furniture-07#0 product-furniture-03#0 policy-shipping#0]
  entry_sources=[policy-returns-electronics#0 policy-returns-furniture#0 product-headphones-10#0 policy-warranty#0 product-headphones-04#0]
```

`similarity_only=true` while `reuse=false` **is** C1's signal: a fixed-threshold baseline (config
3, GPTCache's rule) would have served the headphones answer to a question about a desk. Both
chunk-ID lists print, so the intersection — 2 shared of 5 = 0.40 — is verifiable by eye rather
than taken on trust. All numbers non-citable (`dev-v0`, demo θ/τ, functional run).

**Shipped:** `embed/client.go` (Ollama `/api/embed`, `search_query: ` prefix, dim validated
against ADR-003's 768), `cache/tier2.go` (`idx:cache` FLAT/COSINE, `t2:` records, KNN, hit_count),
`reuse/rule.go` (asymmetric containment, pure, zero non-stdlib imports), `ragclient/retrieve.go`,
`httpapi/cascade.go`, plus handler/main wiring. `make verify` exit 0 throughout.

**Layering ruling, recorded because a future reviewer will question it.** The cascade is
orchestrated in `httpapi/cascade.go`, not in `cache/` or `reuse/`. `httpapi` is the leftmost
package and may import rightward; `reuse/` may not touch Redis or gRPC, because staying
infrastructure-free is what lets C1 be falsified in isolation (architecture.md §2). So **`reuse/`
owns the decision, `httpapi/` owns the plumbing.** ⚠️ `reuse/doc.go` currently claims the package
owns "the overlap rule **and the cascade**", which contradicts the guardrail table — needs an ADR
narrowing it, or someone will "fix" the inconsistency by moving Redis into `reuse/`.

**Tests: 7 table tests on `reuse/` only**, per the rigor decision. They are a thesis artifact, not
coverage — each pins a property whose drift would leave the rule looking like it still worked:
asymmetry (blocks a "simplification" into Jaccard), the two measured demo overlaps as regression
pins, the six-value granularity at `top_k=5`, inclusive `≥` at the θ boundary (the documented
false-hit case at exactly 0.60 must not silently vanish), and `SimilarityOnly` as the baseline
counterfactual.

**Stage timings, captured now rather than retrofitted** (interfaces.md §F). On a `TIER2_HIT`:
`t_tier1=170µs · t_embed=19.1ms · t_search=1.2ms · t_overlap=19.4ms`. **The embedding round-trip
is roughly half the hit path** — which is precisely why §F forbids reporting hit latency as a
single number, and it is an early signal for what bounds μ_hit.

**Decisions:** three, none needing an ADR yet.

1. **Two zones, not three.** No short-circuit band. Every candidate above τ pays a `Retrieve` and
   gets an overlap score, so both numbers reach every response. A high-similarity short-circuit
   would have sent the 0.935 paraphrase down a path rendering `source_overlap: null` — deleting
   the demo's best evidence to save latency that `make dev` forbids citing. `EnteredBand` is
   recorded on every request so the third zone is purely additive later.
2. **`model_used` is a Go-side constant** (`qwen3.5-2b`). §D's Tier-2 schema has no `model_used`
   field, and §A defines it as a constant. Adding a field to a frozen schema needs an ADR;
   fetching the co-written Tier-1 record on every hit puts an extra round-trip on the path that
   bounds μ_hit. Drift risk is bounded — routing was rejected (ADR-011), so this changes only when
   the generation model does, which already requires an ADR touching both sides.
3. **τ and θ read from `REUSE_TAU` / `REUSE_THETA`**, defaulting to the demo values, and the
   gateway prints them at startup labelled *"DEMO values, swept later"*. When the advisor asks
   "what about τ = 0.86?", that is a five-second restart rather than an argument.

**Deferred, recorded so they are not lost:**
- **`PutBoth`** — `t1_key` is currently derived by calling `Key(Normalize(q))` in the handler and
  again inside `Put`. Same function, same input, so they cannot differ today, but the invariant
  would be better enforced structurally by one write method that normalises once. Verified
  empirically instead: `HGET t2:… t1_key` → `EXISTS` → 1, and `entry_id` identical across tiers.
- **Tests on the Redis and HTTP plumbing** — deliberately skipped this week.
- **Double embedding on the cascade band** — Go embeds for the KNN, then `retrieve.py` re-embeds
  inside LlamaIndex. Two Ollama round-trips per band request. Not a bug, but §F requires the
  decomposition be honest about it. Do **not** "fix" it by editing the proto (rules.md #4).
- **`make demo-reset` is still a `TODO(W7)` echo.** Before the pitch it must `FLUSHALL` — never
  `FT.DROPINDEX`, which would leave orphaned `t2:*` hashes that the next startup re-indexes,
  producing a warm cache pretending to be cold.

**Blockers:** none. F1 (`OLLAMA_NUM_PARALLEL`) and the pressure-sensor reboot test still block W8's
μ_hit probe, not the pitch.

**Next:** Day 4 — slides first, then the debug UI if time remains.

**Three findings worth keeping, because they cost real effort and will matter at Phase 4:**

1. **⚠️ A vacuous-pass acceptance criterion, written by me, in a repo whose whole discipline is
   catching those.** The plan claimed `go test ./internal/reuse/...` proved
   `TestNormalizeDoesNotStemOrDropStopwords` still guards the shipped `Normalize`. That test lives
   in `internal/cache/`. Verified directly:
   `go test ./internal/reuse/... -run TestNormalizeDoesNotStemOrDropStopwords` →
   `testing: warning: no tests to run` … `PASS`. Green while executing nothing. **Any future
   acceptance criterion naming that guard must use `./internal/...`.**

2. **The cascade band has bounds but no defined quantity.** `experiment-protocol.md` §5 counts it
   as one of the rule's three free parameters, but nothing in the repo says what it is a band
   *on* — `entered_band` is a boolean in both §H and the protocol. Bounds cannot be pinned before
   the quantity is defined (it is the similarity interval `[τ, τ_high)`), and the shipped gateway
   is deliberately **two-zone**, so `τ_high` does not exist in code yet.

3. **`Final_Proposal.md` §9.4 already admits the gap**, verbatim: *"θ's range is not stated
   anywhere"*, τ's granularity unstated, band bounds unspecified, and *"the best fixed threshold"
   has no written selection objective.* It also names the fix location — `experiment-protocol.md`,
   *"before the sweep runs"*. So the later tuning stage is discharging a debt the proposal already
   booked, not inventing scope.

`Final_Proposal.md` §9.2 say "natural clusters / generated paraphrases / constructed traps";
`data-card.md` §2 and `experiment-protocol.md` §5 say A / B-within / B-cross / C / D.
